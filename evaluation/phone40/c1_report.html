Phone40 Pipeline Accuracy

11 October 2026 40 phone recordings · 39 min · 2 devices both pipelines scored

This page measures how accurately two speech pipelines turn 40 recorded doctor dictations into chart facts (drugs, doses, vitals, allergies), where the medical words are lost, and whether gpt-4.1's output is always correctly formatted.

Use C1 (MedASR + fuzzy matcher + gpt-4.1) as the pipeline stands today. It gets 92.6% of facts right (212 of 229). C2 (Whisper large-v3 + MedASR second pass + fuzzy matcher + gpt-4.1) gets 84.3% (193 of 229). On the same facts C1 wins 22 to 3, exact McNemar p = 0.0002.

C2 actually hears better. Its word error rate is 7.2% against 17.6%, it gets 55 of 61 drug names exactly against 47, and it invents fewer drugs (4 against 9). It loses because large-v3 writes 16 of the 40 dictations as one long comma-joined sentence. The extractor reads "denies… no known drug allergy" in that same sentence and marks 11 prescribed drugs as not given, which also voids their doses. That accounts for 20 of the 22 facts C2 loses.

gpt-4.1 is well behaved but adds no accuracy in either pipeline. All 40 replies were valid JSON inside the closed shortlist, no correct fact was damaged, and each pipeline scores exactly the same with and without it.

If the negation scope is fixed to stop at commas, C2 is the likely winner: with negation set aside it scores 93.9% against C1's 92.6%. Because its transcripts are cached, C2 can be re-scored in minutes once that fix exists.

Why C2 scores lower: one punctuation problem

MedASR writes short sentences. large-v3, with the medical prompt, often writes the whole dictation as one sentence joined by commas. In 16 of the 40 C2 transcripts there are more than 40 words per full stop; C1 has none.

s14, large-v3: "… denies breathlessness, no known drug allergy, no past major illness, … plan,
               ciprofloxacin 500 mg twice daily, paracetamol, hydration watch, …"
extractor:     ciprofloxacin 500 mg  →  negated = true   (scored wrong: drug and dose)

The extractor looks for a negation word anywhere in the sentence that holds the drug. With the whole dictation in one sentence, "denies" and "no known drug allergy" negate every prescription. Affected: azithromycin (s11), ciprofloxacin (s14), nitrofurantoin (s15), metformin (s17), albendazole (s19), ondansetron (s20), pantoprazole (s29, s35), paracetamol (s31), aspirin and atorvastatin (s40). This is a fault in how the pipeline reads large-v3's punctuation, not in what large-v3 heard.

How the fuzzy search works in this pipeline

The fuzzy search sits between the transcript and the chart. It decides which odd-looking words might be misheard medicines, finds the closest real names, and passes a short list to gpt-4.1, which may only answer from that list.

  1. Pick candidate words. A word is considered if it is at least 6 letters, not an ordinary English word or stopword, not already an exact drug name, and not already on a drug row. Context repair also needs a medicine cue word in the sentence (take, tablet, injection, given, prescribed…). A word followed by a dose ("Amoxyclin 500 mg") goes down the dosed path instead.
  2. Score it against the drug reference. The word is compared with names in the India drug reference (about 2,500 substances and 72,000 brands) using difflib's ratio: 2 × matching letters ÷ total letters. Only names of similar length are scanned, with two cheap pre-filters before the full score.
  3. Keep a shortlist. A name stays if it clears the floor for its path (0.84 for a mention with no dose, 0.78 for context repair, 0.55–0.60 against the 33-drug mini list when a dose follows) and is within a band of the best score (0.06–0.10). Synonyms are merged and the list is cut to the top 4–6.
  4. Ask gpt-4.1. The sentence and shortlist go to gpt-4.1, which must return strict JSON: {"decision": "candidate"|"none", "chosen": …, "confidence": …} for context repair, or {"status": "corrected"|"ambiguous", "chosen_token": …, "semantic_confidence_score": …} for term validation.
  5. Check the answer. The JSON must parse, the chosen name must be on the shortlist, and confidence must be at least 0.85; anything else counts as "none". A repaired row is never better than RED and a validated row never better than YELLOW, so a person confirms it.

Data and ground truth

  • Audio: s1.mp4–s40.mp4, AAC, 45–72 s each, recorded 10 October 2026 on two Android phones.
  • Scripts: 40 synthetic dictations from Markdown to PDF (6).md, with PDF watermark text removed and line-broken words rejoined. Generic drug names only, numbers spelled out.
  • Clip-to-script mapping by content: six recordings are not in script order. s11 reads Script 12, s12 reads 11, s27 reads 29, s29 reads 27, s32 reads 35, s35 reads 32. Every match beats its runner-up by at least 0.38.
  • Gold: drafted from the script text by the pipeline's extractor plus a reference scan, then 28 logged corrections (investigations and diet words removed, negations fixed, conditional drugs and supplements marked borderline, as in the earlier gold). The user approved it on 11 October 2026, before any arm was scored. It totals 61 drugs, 23 doses, 142 vitals and 3 allergies.
  • Split: odd clips as dev, even clips as held-out, each with 5 Samsung clips. Both are reported because no tuning was done in this round.

Limitations

  • Read synthetic scripts with common generic names. There are few misspellings for the fuzzy matcher or LLM to fix, so this set cannot show much LLM gain. Brand-heavy or conversational speech would test it harder.
  • The C2 result depends on one large-v3 setting (prompted beam search). A setting that punctuates differently could avoid the run-on sentences.
  • Speakers sometimes depart from the script; s1 says "twice daily" where the script says "thrice daily". Gold follows the script.
  • The gold was checked by one reviewer and is not clinician-reviewed. The extra-row counts depend on gold choices, such as treating investigations as non-drugs.
  • Only gpt-4.1 with the shipped repair prompt was tested; prompt tuning was deferred.
  • 40 clips give intervals of about ±4 points. The C2 vs C1 gap is significant; differences of 1–2 facts are not.
  • WER counts British and US spellings as errors (anaemia vs anemia).

Recommendations

  1. Ship C1 (MedASR first) for now. It is the more accurate pipeline as built: 92.6% against 84.3%.
  2. Fix negation scope, then re-score C2. Stop a negation at the next comma or clause boundary, or re-punctuate large-v3 output before extraction. C2's transcripts are cached, so the re-score takes minutes and needs no new decoding. If C2 then beats C1, prefer it: it hears drug names better (55 vs 47 exact) and invents fewer drugs (4 vs 9).
  3. Fix the misses before the LLM. Add "as needed" and similar phrases to the cue words, or let a ≥ 0.80 match reach context repair. Write negated drug mentions as negated rows. Split hyphenated combination names. Add dispensing data for tiotropium.
  4. Stop the mini-list matcher from inventing drugs. Raise its 0.55–0.60 floor, or send its low-score matches to the LLM instead of straight to a RED row.
  5. Keep gpt-4.1 term validation as a safety check, not an accuracy lever. It is cheap, always well formed, and caused no damage, but it changed no scored fact in either pipeline.
  6. Keep the denoiser at none for phone dictation of this quality.

Reproduce

# C1 (MedASR first)
MEDIBYTES_LLM_TRACE=runs/phone40/C1/trace.jsonl python -m base_pipeline.run <audio> --preset context-repair \
  --model medasr --llm-url https://api.openai.com/v1 --llm-model gpt-4.1 --llm-env .env --out runs/phone40/C1
# C2 (large-v3 first, MedASR second pass)
MEDIBYTES_ASR_STRICT=1 MEDIBYTES_ASR_CACHE=runs/phone40/asr_cache MEDIBYTES_LLM_TRACE=runs/phone40/C2/trace.jsonl \
  python -m base_pipeline.run <audio> --preset context-repair --model large-v3 --decode beam5-en-fallback-prompt \
  --second-pass medasr --llm-url https://api.openai.com/v1 --llm-model gpt-4.1 --llm-env .env --out runs/phone40/C2
# No-LLM controls: the same commands with --preset regex-only (A0, A0_large)
# Score
python -m clinical_eval.fact_score runs/phone40/C2 --gold experiments/phone40/gold.json --split experiments/phone40/split.json --compare runs/phone40/C1
python -m clinical_eval.repair_score runs/phone40/C2 --gold experiments/phone40/gold.json --split experiments/phone40/split.json --baseline runs/phone40/A0_large
python -m clinical_eval.repair_score runs/phone40/A0 --gold experiments/phone40/gold.json --gate sherpa-gtcrn-simple
python experiments/phone40/collect.py > runs/phone40/summary.json
